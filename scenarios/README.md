# Test scenarios (all synthetic and fictional)

## Recall test (`func_bench.py`, `run_bench.sh func`)
`recall/hay_{2k,4k,8k,16k,32k}.txt` are the engineering notes of a fictional project ("Project Kestrel"),
generated by `python3 func_bench.py gen` (seed 20261111; regenerating gives byte-identical files). Each one holds the SAME
10 facts (`recall/needles.json`) at ~5 %, 15 %, ... 95 % of the text; the question block (`recall/question_block.txt`) asks for
all 10 as `key=value` lines and for `key=NOT_FOUND` when a value is not in the notes.
With the Qwen3 tokenizer the full prompts are 1,601 / 3,427 / 7,432 / 15,143 / 30,989 tokens, so each fits in a context
of its nominal size (2048 ... 32768) with room for the 256-token answer.

A spec `DOC:CTX:KV` with CTX smaller than DOC drops paragraphs from the START of the notes until the prompt fits,
so the early facts are gone: `needles_in_context` says how many survived. Statuses per fact:
correct / not_found (model said it is not there) / wrong (invented or mixed up) / missing (no line).

## Developer scenario (`dev_bench.py`, `run_bench.sh dev`)
`dev_questions.json` holds 21 tasks: shell, git, Termux, regex, error explanations, bug fixes in Python/JS/SQL, small
functions with hidden tests, and questions about `dev_fixtures/inventory_service.py` (~4.3-4.5k tokens when pasted).
The fixture file contains one deliberate bug (`bulk_discount_pct`, task L3).
The `reference` / `wrong` answers are only used by `python3 dev_bench.py selftest`.
